# Contributing

Thanks for your interest in improving a [docxology](https://github.com/docxology) project. This guide applies to every repository that does not ship its own `CONTRIBUTING.md`.

## Before you start

- Check open issues and pull requests to avoid duplicate work.
- For anything larger than a small fix, open an issue first so we can agree on the approach.
- Security problems: please follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

## Making a change

1. Fork the repository and create a branch from the default branch.
2. Keep changes focused; one topic per pull request.
3. Follow the repository's own conventions (see its `README.md`, `AGENTS.md` or `CLAUDE.md` where present).
4. Run the project's tests or validators locally before opening the pull request.
5. Update documentation and changelogs that your change affects.

## Pull requests

- Describe what changed and why, and link related issues.
- Make sure CI passes. Maintainers may ask for revisions.
- By contributing you agree that your contribution is licensed under the repository's license.

## Research content

Many repositories hold manuscripts, datasets and teaching materials. Cite sources, keep provenance for data, and do not add material you do not have the right to share.
